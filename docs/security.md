# Security Threat Checklist & Controls

| Risk | Attack Vector | Mitigation & Code Location |
|---|---|---|
| **SQL Injection** | Malicious SQL in search query, barcode, or filter params | Every query uses `?` bound parameters in `node:sqlite` (`backend/src/modules/*/repository.js`). FTS5 search strips operators and quotes tokens in `buildSafeFtsQuery` (`backend/src/modules/books/repository.js`); `sort` columns map through an explicit `SORT_COLUMN_MAP` whitelist. |
| **Broken Access Control (IDOR)** | Member A attempting to renew or cancel Member B's loan or reservation | `loans/service.js` (`renewLoan`) and `reservations/service.js` (`cancelReservation`) verify `record.member_id === user.memberId` for `member` role. Verified by `backend/tests/authorization.test.js`. |
| **Privilege Escalation** | Member calling admin/librarian endpoints or self-assigning `role` | `requireRole` middleware (`backend/src/middleware/requireRole.js`) enforces RBAC on every route; `POST /fines/:id/waive`, `/users`, `/loan-policies/:memberType`, and `/audit-log` require `admin`; Zod schemas strip unknown fields. |
| **Weak Passwords & Credential Stuffing** | Brute-force login or weak password registration | `backend/src/utils/password.js` hashes with `crypto.scrypt` (random 16-byte salt, `N=16384`, `timingSafeEqual`). Login returns a generic error message and is rate-limited via `authLimiter` in `backend/src/app.js`. |
| **Refresh Token Theft / Replay** | Replaying a previously rotated refresh token | `refresh_tokens` stores only SHA-256 hashes (`backend/src/utils/tokens.js`). `auth/service.js` (`refresh`) detects reuse of a revoked token and immediately revokes **all** refresh tokens for that user. |
| **XSS** | Stored HTML/script inside book titles or descriptions | API emits JSON only; Helmet enforces strict CSP (`script-src 'self'`, `object-src 'none'`, `frame-ancestors 'none'`) in `backend/src/app.js`; frontend escapes every dynamic value with `escapeHtml()` (`frontend/js/ui/format.js`). |
| **CSRF** | Cross-site requests exploiting refresh cookies | Refresh cookie is `HttpOnly; SameSite=Strict; Path=/api/v1/auth` (`auth/controller.js`) AND `requireCsrfHeader` (`backend/src/middleware/csrfHeader.js`) requires `X-Requested-With` on `/auth/refresh` and `/auth/logout`. |
| **Excessive Requests / DoS** | High-volume scraping or login flooding | `express-rate-limit` global (`/api/v1`), strict auth (`/auth/*`), and public catalogue search limiters in `backend/src/app.js`. |
| **Sensitive Data Exposure** | Leaking `password_hash`, tokens, or PII in API responses or logs | `sanitizeProfile` strips `password_hash`; `backend/src/utils/logger.js` (`redactObject`) redacts passwords, tokens, cookies, emails, and phones; `errorHandler.js` never emits stack traces. |
| **Mass Assignment & Input Abuse** | Injecting `role`, oversized pages, or malformed ISBNs | Every `body`, `query`, and `params` goes through strict Zod schemas (`backend/src/middleware/validate.js`), capping `limit <= 50` and `q <= 120`. |
| **Accountability** | Untracked circulation or fine adjustments | Database triggers (`db/migrations/005_triggers.sql`) log every `INSERT`/`UPDATE` on `loans`, `fines`, and `reservations` to `audit_log` with `actor_user_id` and JSON snapshots; `requestIdMiddleware` attaches `X-Request-Id`. |
